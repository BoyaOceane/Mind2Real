# 即墨 — 功能文档

> 记录 index.html 和 story.html 的完整功能逻辑，用于还原和交接。

---

## 一、项目概述

**即墨**是一个 AI 驱动的分支叙事小说生成工具。

用户不需要会写小说，只需要会"选"和"说"：
- **选**：在关键节点从 AI 提供的选项中挑选剧情走向
- **说**：用自然语言描述想要的剧情方向，AI 负责专业地执行

**两个核心页面**：
- `index.html` — 创作起点，生成世界观和主角，开始创作
- `story.html` — 故事阅读与分支叙事，沉浸式创作体验

---

## 二、index.html 功能详解

### 页面定位
创作入口页。用户在此完成世界观和主角的设定，然后进入 story.html 开始写故事。

### 顶部顶栏（深色）
- 项目名"即墨"
- "历史记录"按钮 — 点击展开历史故事列表
- "API 设置"按钮 — 展开 DeepSeek API Key 输入框

### 主要内容区（三张卡片）

#### 卡片1：世界背景
- **输入**：一个 `<textarea>`，用户用自然语言描述想要的设定（如"发生在民国上海的谍战故事"）
- **生成按钮**：调用 DeepSeek API，根据输入生成完整世界观
- **生成内容**（存储在 localStorage）：
  - `worldTitle`：世界名称
  - `worldDesc`：世界观描述（AI 会用通俗语言，避免文学腔）
  - `worldTags`：标签数组，如 `["民国", "谍战", "上海"]`
  - `goldenFinger`：主角的金手指/特殊能力
  - `narrative`：叙事风格描述（如"冷峻克制，白描为主"）
- **状态**：未生成时显示输入框+生成按钮；生成后显示世界名+标签+描述+重新生成按钮

#### 卡片2：主角设定
- **生成按钮**：直接调用 API 生成主角
- **生成内容**：
  - `protagonist`：主角名字
  - `protagonistTags`：主角性格标签数组
  - `protagonistStyle`：风格标记（`'chinese'` 或 `'western'`），影响人物关系图的布局
- **状态**：未生成时显示生成按钮；生成后显示主角名+标签+重新生成按钮

#### 卡片3：叙事风格
- 显示当前叙事风格描述（从世界背景卡片继承来的 `narrative` 字段）
- 仅展示，不可独立修改，随世界背景一起生成

### 固定底部 CTA 栏
- **位置**：固定在页面底部，不随滚动消失
- **内容**：一个文本输入框 + "开始创作"主按钮
- **输入框 placeholder**：`输入你想要的剧情方向...`
- **按钮逻辑**：
  - 点击后检查：是否已生成世界背景、是否已配置 API Key
  - 验证通过后，将 `current_story_session` 数据写入 localStorage，跳转到 `story.html`
  - 验证失败时显示 toast 提示（"请先生成世界背景" / "请先设置 API Key"）

### 历史记录侧面板
- 点击"历史记录"按钮展开右侧面板（overlay）
- 列表显示最近 50 条故事，每条包含：
  - 标题（世界名 + "- 故事"）
  - 保存日期
  - 点击后跳转 story.html 并加载该故事
  - 删除按钮（删除单条）
- 面板外点击或点 X 关闭

### API 设置
- 点击"API 设置"展开输入框
- 输入 DeepSeek API Key 后保存到 `deepseek_api_key`（localStorage）
- 也可选择模型（`deepseek_model`，默认 `flash`）
- 设置后折叠面板

### localStorage 数据结构

```javascript
// 创作session（跳转story.html时写入）
localStorage.setItem('current_story_session', JSON.stringify({
  worldTitle: String,
  worldDesc: String,
  worldTags: String[],
  protagonist: String,
  protagonistTags: String[],
  goldenFinger: String,
  narrative: String,
  history: Array<{ content: String, options: Array<{title, desc}> }>
}));

// 历史记录（每次故事保存时更新）
localStorage.setItem('story_history', JSON.stringify(Array<{
  _autoId: String,        // 自动保存ID
  title: String,
  date: String,           // "YYYY/MM/DD HH:mm"
  content: String,
  worldTitle: String,
  protagonist: String
}>));

// API配置
localStorage.setItem('deepseek_api_key', String);
localStorage.setItem('deepseek_model', String);
```

## 三、story.html 功能详解

### 页面定位
故事阅读与分支创作页。用户在此阅读 AI 生成的故事，选择或输入剧情走向，AI 继续续写。

### 顶栏（深色）
- **返回按钮**：`← 返回` 回到 index.html
- **故事标题**：显示当前世界名
- **保存按钮**：`btn-save` — 弹出 prompt 让用户自定义标题，然后保存到 `story_history`
- **导出按钮**：`btn-export` — 将故事正文导出为 `.txt` 文件下载

### 页面主体布局（三栏）

```
┌──────────────────────────────────────────────────────┐
│  [← 返回]    故事标题              [保存] [导出]      │  ← 顶栏（深色）
├──────────────────────────────────────────────────────┤
│                                    │ 时间线 │ 侧边栏 │
│         故事内容区                  │ (32px) │(220px) │
│      （主阅读区域）                 │        │        │
│                                    │        │ 提纲   │
│                                    │        │ 线索   │
│                                    │        │ 人物   │
├──────────────────────────────────────────────────────┤
│              世界信息横幅                            │
├──────────────────────────────────────────────────────┤
│  输入框                    [继续创作]  ← 固定底栏    │
└──────────────────────────────────────────────────────┘
```

### 世界信息横幅（World Banner）
- 显示世界名 + 标签（`.tag` 样式）+ 主角名 + 叙事风格
- 加载时从 `current_story_session` 读取并展示

### 故事内容区（Story Content）
- **首屏**：如果 `history` 为空，调用 `generateOpening()` 生成开篇
- **已有历史**：将 `history` 数组中的所有 `content` 用 `<hr class="story-divider">` 分隔拼接成分段故事
- **正文样式**：
  - 每段 `<p>` 首行缩进 2em（`text-indent: 2em`）
  - 选项行（如 `A. xxx`）有特殊样式：左边的金色边条 + 颜色高亮（`.choice-line`）
  - 分隔符：横向渐变线 + 中间菱形符号
- **加载状态**：生成中时显示三个跳动的点 + "创作中..."

### 分支选项（Options）
- **触发时机**：每次故事生成完毕后，AI 会解析出选项，存入 `currentOptions`
- **选项卡片**：显示 A/B/C/D/E 五个选项，每个卡片包含字母标识 + 标题
- **交互**：
  - 点击卡片 → 选中该选项，`selectedOption` 更新，卡片高亮
  - 选中后 `continueHint` 文字变为"已选择：xxx"
  - 选中后可点击"继续创作"按选定方向继续
- **选项刷新**：如用户不满意，可调用 `refreshOptions()` 重新生成3个差异化选项

### 固定底栏（Bottom Action Bar）
- **位置**：固定在页面底部，毛玻璃半透明背景
- **内容**：
  - 提示文字（`.continue-hint`）：默认"输入剧情方向，或直接点击继续"
  - 输入框（`#customInput`）：用户输入自定义剧情方向
  - "继续创作"按钮（`#btnContinue`）
- **交互**：
  - 输入框有内容时，提示变为"将按自定义剧情继续"
  - 按 `Ctrl+Enter` / `Cmd+Enter` 快速触发继续
  - 按钮 disabled 状态：生成中禁止重复点击

### 右侧边栏（Story Sidebar，220px）

#### 标签页切换
- 三个 tab：提纲 / 线索 / 人物
- 点击切换显示对应面板内容

#### 时间线（Timeline，32px宽）
- 垂直节点条，显示在侧边栏左侧
- 每个节点颜色对应重要性：
  - `critical`（重点）→ 红色 `#c97a7a`
  - `major`（较重要）→ 橙色 `#c9a060`
  - `normal`（普通）→ 灰色 `#b0a99e`
- hover 节点会放大，并显示 tooltip（剧情摘要）
- 节点数取决于当前选中的 tab 内容（提纲tab→提纲节点；线索tab→线索节点）

#### 提纲面板（Outline）
- 列表展示所有剧情提纲节点
- 每条带重要性色点 + 摘要文字

#### 线索面板（Clues）
- 列表展示所有线索
- 每条包含：线索名 + 描述 + 状态标签（如"伏笔→展开"）

#### 人物面板（Characters）
- 列表展示所有出场角色
- 每条：头像圆圈（首字）+ 名字 + 关系
- 底部渲染角色关系图（SVG）：主角在左，其他角色在右，弧线连接

### AI 生成逻辑

#### 开篇生成（`generateOpening`）
- 检查 API Key，没有则提示并跳转 index.html
- 拼接 prompt：世界背景 + 主角 + 金手指 + 叙事风格 + 用户偏好（`user_preference`）
- 系统提示词（system prompt）包含完整的【写作八条铁律】和【剧情打点】格式要求
- 流式输出：每收到一个 chunk 就实时渲染到页面
- 完成后：
  1. 调用 `ensureCompleteSentence()` 确保末尾是完整句
  2. 调用 `stripStructuredMeta()` 去掉元数据只要正文
  3. 调用 `parseOptions()` 从正文中提取 A/B/C 选项
  4. 调用 `appendNewMeta()` 解析【剧情打点】更新侧边栏内容
  5. 存入 `history` + `saveStoryData()` + `autoSave()`

#### 继续创作（`continueStory`）
- 获取用户输入（自定义输入 or "继续发展剧情"）
- 拼接已有 `history` 内容作为上下文
- 同样调用完整系统提示词
- 流程同上

#### 选项刷新（`refreshOptions`）
- 用最后一段故事内容调用 DeepSeek
- prompt 中要求生成3个差异化选项
- 解析后更新 `currentOptions` 和对应 history 条目

### 剧情打点（Structured Metadata）

AI 在每次生成的故事末尾，会返回带结构化标记的元数据，格式如下：

```
【剧情打点】
[提纲节点]
转折 | critical | 主角发现密室暗门
悬念 | major | 神秘人留下警告信

[线索节点]
古宅秘宝 | 伏笔→展开 | 地图碎片出现 | major

[人物节点]
李管家 | 首次出场 | 与主角：主仆 | 古宅管家，知道秘密
```

解析后分别更新：
- `storyOutline[]` — 提纲节点数组
- `storyClues[]` — 线索数组（同名线索状态合并，不重复创建）
- `characterCards[]` — 人物卡数组（新人物才追加，已有时只更新字段）

### 保存与导出

#### 自动保存（`autoSave`）
- 每次生成新段落后自动执行
- 写入 `story_history`，用 `_autoId` 标记同一次创作的不同段落
- 同一 `_autoId` 的多次 autoSave 只会保留最新版本（覆盖）

#### 手动保存（`saveStory`）
- 弹出 prompt 让用户自定义标题
- 同样写入 `story_history`，覆盖同 `_autoId` 的旧记录

#### 导出（`exportStory`）
- 将 `history` 中所有 `content` 用 `\n\n---\n\n` 连接
- 生成 Blob 下载为 `.txt` 文件

## 四、API 集成

### 调用方式
```javascript
POST https://api.deepseek.com/v1/chat/completions
Headers: Authorization: Bearer {apiKey}
Body: {
  model: "deepseek-v4-pro",
  messages: [
    { role: "system", content: systemPrompt },
    { role: "user", content: userPrompt }
  ],
  max_tokens: 252,
  temperature: 0.8,
  stream: true   // 流式输出
}
```

### 系统提示词核心约束（写作铁律）
1. 第三人称开场，直接进入冲突
2. 首句必须有异常、不安或未解之谜
3. 每千字必须有情绪转折或情节推高
4. 不直接描写心理，用动作和对话暗示
5. 克制数字：不用精确数值，用感官代替测量
6. 每段必须在句号处截断（不得在逗号处断句）
7. 字数严格控制在 252 字以内（不含打点）

## 五、用户操作完整流程

```
index.html
  │
  ├─ 输入世界背景描述 → 点击"生成" → AI 生成世界观（金手指、叙事风格）
  │
  ├─ 点击"生成"主角 → AI 生成主角名字+性格标签
  │
  ├─ 填写 API Key（如首次）
  │
  └─ 输入剧情方向（可选）→ 点击"开始创作"
        │
        ▼
story.html（加载 current_story_session）
  │
  ├─ AI 生成开篇故事（流式输出）
  │
  ├─ 展示选项 A/B/C
  │
  ├─ 用户选择选项 OR 输入自定义剧情
  │
  ├─ AI 续写（流式输出）
  │
  ├─ 侧边栏实时更新（提纲/线索/人物 + 时间线节点）
  │
  ├─ 循环：选/输入 → 续写 → 展示选项
  │
  ├─ 保存到历史记录（自动+手动）
  │
  └─ 导出为 txt 文件
```

## 六、admin.html 提示词管理页面

### 页面定位
集中管理所有 AI 提示词的配置页面。让运营者无需修改代码即可调整 AI 的行为逻辑。

### 入口
在 index.html 顶栏提供"提示词管理"按钮，点击进入 admin.html。

### 管理板块

| 板块 | 对应功能 | 参考文档 |
|------|---------|---------|
| **世界观生成** | 生成世界背景、金手指、叙事风格 | `docs/世界背景.md` |
| **主角生成** | 生成主角名字、性格标签 | `docs/人物性格中式.md`、`docs/人物性格西式.md` |
| **故事续写** | 核心写作系统提示词 | `docs/八大准则.md` |
| **选项生成** | 生成关键节点的可选剧情分支 | `docs/叙事方式.md` |

### 每个板块的 Tag 参考

#### 世界观生成 — 参考 `docs/世界背景.md`

**按物理规律划分**：现实世界、规则世界、星际世界、平行世界、微观世界、数据世界、梦境世界

**按时代位置划分**：古代世界、近代世界、现代世界、近未来世界、远未来世界、末日世界、后末日世界

**按技术路线划分**：蒸汽朋克、赛博朋克、柴油朋克、原子朋克、生物朋克、丝绸朋克、石器朋克

**按超自然力量划分**：无魔世界、低魔世界、高魔世界、神话世界、克苏鲁世界、灵异世界

**按文明形态划分**：部落世界、城邦世界、帝国世界、封建世界、资本世界、共产世界、无政府世界、蜂巢世界

**按存在状态划分**：物质世界、精神世界、模拟世界、书中世界、死后世界、转生世界

**按异化方向划分**：废土世界、异星世界、深海世界、地下世界、浮空世界、巨构世界

#### 主角生成 — 参考 `docs/人物性格中式.md` / `docs/人物性格西式.md`

**中式主角 Tag（五大维度）**：
- **气质底色**：天生领头者、柔韧适应者、热情感染型、外冷内热型、稳重可靠型、细腻滋养型、杀伐果断型、精致挑剔型、自由奔放型、神秘直觉型
- **能量状态**：主动进攻型、以守为攻型、极端偏执型
- **处事风格**：规矩守成型、野心攻击型、温和包容型、孤僻奇才型、踏实积累型、洒脱挥霍型、随遇而安型、毒舌叛逆型、独立自尊型、冲动义气型
- **人格面具**：天生领袖范、机灵多变型、热心操劳型、刚毅果断型、乐天知足型、亦正亦邪型、稳重守成型、温柔策划型、贪多求全型、直言惹祸型、公正调和型、爱管闲事型、敢爱敢恨型
- **内在驱动**：自我实现驱动、财富积累驱动、事业成就驱动、情感关系驱动、自由漂泊驱动

**西式主角 Tag（六大维度）**：
- **性格内核**：高/低神经质、高/低宜人性、高/低尽责性、高/低外向性、高/低开放性、自恋型、马基雅维利型、精神病态型、完美主义、冲动型、回避型、偏执型
- **内在驱动**：成就驱动、权力驱动、亲和驱动、认知驱动、生存驱动
- **关系模式**：安全型、焦虑型、回避型依恋、紊乱型
- **心理防线**：升华型、幽默型、利他型、合理化、置换型、投射型、否认型、退行型
- **创伤印记**：童年忽视、背叛创伤、幸存者愧疚、代际创伤、创伤后成长
- **自我认知**：高/低自尊、内/外控型、自我清晰、自我混乱

#### 故事续写 — 参考 `docs/八大准则.md`

**写作八条铁律**：
1. **钩子**：首句包含异常/不安/未解之谜
2. **感受优先**：情绪在前，用动作和对话暗示，不直接描写心理
3. **节奏控制**：每千字有情绪转折或情节推高，平静段落必须埋暗流
4. **规则要演**：每引入设定，立即有角色因这条规则改变命运
5. **行动即人设**：不给角色贴标签，只写关键时刻的选择
6. **爽点兑现**：至少兑现翻身/解密/占有/自由/活下来/守护之一
7. **语言透明**：删形容词、删心理描写、删炫技句子
8. **考据隐身**：虚构设定锚定真实知识体系，专业信息隐入动作/对话/环境

#### 选项生成 — 参考 `docs/叙事方式.md`

**叙事方式 Tag**：
- **主体聚焦**：人民叙事、英雄叙事、底层叙事、精英叙事
- **认知视角**：全知视角（上帝视角）、限知视角（单一人物视角）、外视角（客观行为主义视角）
- **时态视角**：回溯性叙事（回忆录式倒叙）、共时性叙事（即时性直播感）
- **叙述可靠性**：不可靠叙述、复调叙事
- **结构形式**：元叙事（打破第四面墙）、非线性叙事、碎片化叙事、反转叙事

## 七、story.html 删除选项刷新功能

### 原因
原设计中有 `refreshOptions()` 功能，允许用户刷新不满意选项重新生成。但实际体验中：
1. 用户倾向直接输入自定义剧情方向，较少使用刷新选项
2. 刷新功能增加界面复杂度
3. 减少一次 API 调用，降低成本

### 删除内容
- `refreshOptions()` 函数（story.html 第1019-1062行附近）
- "刷新选项"按钮（如界面中有此入口）
- 选项区的刷新交互逻辑

### 保留功能
- 选项展示（`displayOptions`）
- 选项点击选中（`selectOption`）
- 用户可直接在输入框输入自定义剧情，绕过选项直接续写
