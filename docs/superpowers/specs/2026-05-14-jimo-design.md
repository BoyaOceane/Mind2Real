> **版本：** MVP POC  
> **日期：** 2026-05-14  
> **状态：** 经 Q&A 审计确认

---

## 一、项目概述

**即墨** 是一个 AI 驱动的分支叙事故事生成器。用户通过配置世界观、主角设定、叙事风格三个维度，调用 DeepSeek API 生成连贯的交互式小说。每次生成约 252 字，用户可输入剧情方向引导后续发展，AI 自动维护剧情提纲、线索和人物关系。

**核心原则：**
- 单文件 HTML，内联 CSS/JS，点击即用
- 纯前端，localStorage 持久化
- 流式输出，实时渲染

---

## 二、页面架构

共 **3 个页面**：

| 页面 | 职责 | 文件 |
|------|------|------|
| **创作入口** | 配置故事参数，启动创作 | `index.html` |
| **故事阅读** | 流式阅读、剧情引导、辅助面板 | `story.html` |
| **提示词管理** | 查看/编辑各板块系统提示词 | `admin.html` |

`design.html` 为设计参考稿，**不修改**。

## 三、index.html — 创作入口

## 四、story.html — 故事阅读

### 4.1 顶栏（Top Bar）

固定顶部，包含：
- **API 设置** — 弹出 API Key 输入框
- **提示词管理** — 跳转 `admin.html`
- **保存** — 手动保存当前故事到历史记录
- **导出** — 导出为 `.txt` 文件
- **返回首页** — 跳转 `index.html`

### 4.2 布局顺序（从上到下）

```
top-bar
world-banner（世界背景横幅）
story-content（故事正文区，可滚动）
bottom-action-bar（固定底栏）
```

右侧固定辅助面板（始终可见）：
```
story-timeline（48px 宽，时间线/关系图可视化）
story-sidebar（240px 宽，内容详情）
edge-tabs（切换标签页）
```

### 4.3 世界背景横幅（World Banner）

- 展示当前故事的世界背景摘要
- 浅金色背景，优雅字体

### 4.4 故事正文区（Story Content）

- 最大宽度 640px（为右侧辅助面板让出空间）
- 流式输出时逐字渲染
- 每段 `<p>` 首行缩进 2em
- 分隔符：横向渐变线 + 中间菱形符号
- 生成中时显示"创作中..." + 跳动动画

### 4.5 固定底栏（Bottom Action Bar）

固定在页面底部，毛玻璃半透明背景：
- **提示文字**：默认"输入剧情方向，或直接点击继续"
- **输入框**（`#customInput`）：用户输入自定义剧情方向或建议（可选）
- **"继续创作"按钮**（`#btnContinue`）

**交互：**
- 输入框有内容时，提示变为"将按自定义剧情继续"
- 按 `Ctrl+Enter` / `Cmd+Enter` 快速触发
- 生成中按钮 disabled，防止重复点击

### 4.6 右侧辅助面板

#### 4.6.1 时间线区（Story Timeline，48px 宽）

一条垂直细线（2px，浅灰色）贯穿区域，节点沿时间线分布：

**提纲/线索 Tab 时：**
- 节点为圆点（8-12px），按重要性着色：
  - `critical`（重点）→ 红色 `#e74c3c`
  - `major`（较重要）→ 橙色 `#e67e22`
  - `normal`（普通）→ 灰色 `#bdc3c7`
- 节点之间直线连接
- hover 节点：放大 + 显示 tooltip（剧情摘要）
- 点击节点：story-content 跳转到对应段落

**人物 Tab 时：**
- 显示大脑神经元式关系图
- 主角固定在中心（较大节点，金色）
- 其他角色围绕分布（小节点）
- 直线连接，连线中间标注关系文字
- 点击节点：查看角色详情
- 新角色出现时有脉冲动画

#### 4.6.2 边栏标签（Edge Tabs）

固定在 timeline 右侧边缘的三个书签标签：
- **提纲**
- **线索**
- **人物**

点击切换：sidebar 内容 + timeline 可视化内容同步切换。

#### 4.6.3 边栏内容区（Story Sidebar，240px 宽）

始终可见，显示当前选中 tab 的详情列表：

**提纲面板：**
- 节点列表，带编号、重要性色点、摘要文字
- 点击条目：story-content 跳转到对应段落

**线索面板：**
- 线索卡片列表
- 每条包含：线索名 + 描述 + 简单状态标记（伏笔/明线/暗线）

**人物面板：**
- 人物卡片列表（主角置顶）
- 每条包含：头像圆圈（首字）+ 名字 + 关系

### 4.7 AI 生成逻辑

#### 4.7.1 开篇生成（`generateOpening`）

1. 检查 API Key，没有则提示并跳转 `index.html`
2. 拼接 prompt：世界背景 + 主角设定 + 金手指 + 叙事风格
3. 系统提示词包含完整的【写作八条铁律】和【剧情打点】格式要求
4. 流式输出：每收到一个 chunk 实时渲染到页面
5. 完成后：
   - 调用 `ensureCompleteSentence()` 确保末尾是完整句
   - 调用 `stripStructuredMeta()` 去掉元数据只保留正文
   - 调用 `appendNewMeta()` 解析【剧情打点】更新侧边栏内容
   - 存入 `history` + `saveStoryData()` + `autoSave()`

#### 4.7.2 继续创作（`continueStory`）

1. 获取用户输入（自定义输入或留空）
2. 拼接已有 `history` 内容作为上下文
3. 同样调用完整系统提示词
4. 流程同开篇生成

#### 4.7.3 系统提示词核心约束（写作铁律）

1. 第三人称开场，直接进入冲突
2. 首句必须有异常、不安或未解之谜
3. 每千字必须有情绪转折或情节推高
4. 不直接描写心理，用动作和对话暗示
5. 克制数字：不用精确数值，用感官代替测量
6. 每段必须在句号处截断（不得在逗号处断句）
7. 字数严格控制在 252 字左右（不含打点）

#### 4.7.4 剧情打点（Structured Metadata）

AI 在每次生成的故事末尾返回结构化标记：

```
【剧情打点】
[提纲节点]
转折 | critical | 主角发现密室暗门
悬念 | major | 神秘人留下警告信

[线索节点]
古宅秘宝 | 伏笔 | 地图碎片出现 | major

[人物节点]
李管家 | 首次出场 | 与主角：主仆 | 古宅管家，知道秘密
```

解析后更新：
- `storyOutline[]` — 提纲节点数组
- `storyClues[]` — 线索数组（同名线索状态合并，不重复创建）
- `characterCards[]` — 人物卡数组（新人物才追加，已有时只更新字段）

### 4.8 保存与导出

#### 4.8.1 自动保存（`autoSave`）

- 每次生成新段落后自动执行
- 写入 `story_history`，用 `_autoId` 标记同一次创作的不同段落
- 同一 `_autoId` 的多次 autoSave 只保留最新版本（覆盖）

#### 4.8.2 手动保存（`saveStory`）

- 弹出 prompt 让用户自定义标题
- 同样写入 `story_history`，覆盖同 `_autoId` 的旧记录

#### 4.8.3 导出（`exportStory`）

- 将 `history` 中所有 `content` 用 `\n\n---\n\n` 连接
- 生成 Blob 下载为 `.txt` 文件

## 五、admin.html — 提示词管理

### 5.1 页面定位

集中管理所有 AI 提示词的配置页面。让运营者无需修改代码即可调整 AI 的行为逻辑。

### 5.2 入口

- `index.html` 顶栏"提示词管理"按钮
- `story.html` 顶栏"提示词管理"按钮
- 本页提供"返回"按钮回到上一页

### 5.3 管理板块

| 板块 | 对应功能 | 参考文档 |
|------|---------|---------|
| **世界观生成** | 生成世界背景 | `docs/世界背景.md` |
| **主角生成** | 生成主角名字、性格标签 | `docs/人物性格中式.md`、`docs/人物性格西式.md` |
| **故事续写** | 核心写作系统提示词 | `docs/八大准则.md` |
| **叙事风格** | 叙事方式配置 | `docs/叙事方式.md` |

### 5.4 每个板块的功能

- **查看**：提示词以只读方式展示（带语法高亮/区块分隔）
- **编辑**：点击"编辑"展开 textarea，修改后保存
- **重置**：提供"恢复默认"按钮，将提示词还原为初始值
- **预览**：在编辑界面提供"测试"按钮，用示例输入验证提示词效果

### 5.5 数据存储

提示词配置存储在 `localStorage` 中：

```javascript
localStorage.setItem('prompt_config', JSON.stringify({
  worldPrompt: String,
  protagonistPrompt: String,
  storySystemPrompt: String,
  narrativeStylePrompt: String,
  updatedAt: String  // "YYYY-MM-DD HH:mm"
}));
```

## 六、API 集成

### 6.1 调用方式

```javascript
POST https://api.deepseek.com/v1/chat/completions
Headers: Authorization: Bearer {apiKey}
Body: {
  model: "deepseek-chat",
  messages: [
    { role: "system", content: systemPrompt },
    { role: "user", content: userPrompt }
  ],
  max_tokens: 300,
  temperature: 0.8,
  stream: true   // 流式输出
}
```

### 6.2 参数说明

- **model**：`deepseek-chat`（或用户指定的 DeepSeek 模型）
- **max_tokens**：300（预留空间给剧情打点元数据，正文约 252 字）
- **temperature**：0.8（保持一定创造性）
- **stream**：true（流式输出，实时渲染）
