# 先选路再铺路 — 分支优先续写设计

> **日期：** 2026-07-13
> **阶段：** Phase 6（基于 P0 MVP + P4 文风学习 + P5 历史归档 + 去 AI 味）
> **定位调整：** 即墨 从"AI 故事生成器"转向"故事思维伙伴"

---

## 1. 背景与定位

### 1.1 项目真正的宝贝

即墨 最独特的不在 prose 生成（每个 AI 工具都能写，且项目花 P4 + 去 AI 味两轮在跟 AI 味打架——这是在 AI 的弱项上耗力），而在两样东西：

- **Tag 体系** — 七维世界、五维主角、五维叙事。逼用户把模糊偏好变成显性创作决策，让潜在灵感显形、可组合。
- **剧情打点活模型** — 侧边栏自动维护提纲/线索/人物，故事有"自我记忆"，能记住比人脑更多的线索。

### 1.2 新定位

把重心从"写正文"挪到"看见并塑造可能性"：

- AI 的核心价值不是写下一段，而是基于 tag + 活模型，给出"接下来可以怎么走"的分支
- 用户挑选/塑造分支，更新活模型
- 正文从"产品本身"降级为"反应材料"
- "自己爱看"靠故事走到让用户兴奋的地方；"愿意写"靠用户始终做有意义的创作决策

---

## 2. Goal

将 story.html 的续写交互从"用户输入方向 → AI 直接写正文"改为"AI 给 4 个带钩子的分支 + 第 5 个自己写 → 用户选路 → AI 扩写成正文"，使每次续写都先放大用户对可能性的看见，再落地为文字。

---

## 3. 核心交互

### 3.1 续写循环（变更后）

```
阅读完当前段落
  │
  ├─ 底部按钮："给走向"
  │
  ▼
AI 生成 4 个分支（2-3 句，带钩子）+ 第 5 项"自己写"
  │
  ├─ 用户点某个分支 ──→ AI 按该走向扩写正文（流式）──→ 剧情打点更新侧边栏
  ├─ 用户点"自己写" ──→ 展开输入框 ──→ 用户打字 ──→ AI 按其方向扩写正文
  │
  ▼
分支卡片消失，底部回到"给走向"按钮，循环
```

### 3.2 开场（不变）

进 story.html 仍由 AI 自动生成开篇（~252 字），设定情境、抛出第一个不安。开篇后进入分支循环。开场是铺舞台，分支循环是推剧情。

### 3.3 分支卡片格式

每个分支卡片包含：

- **走向**（2-3 句）：这一步具体怎么发展
- **钩子**：显式连回 tag 体系和剧情打点——牵动哪条线索、哪个人物、情绪如何转折

示例：
> 主角推开暗门，撞见本该死去的旧友。
> **牵动**【古宅秘宝】线索，情绪由疑转惊。

### 3.4 五个选项的约束

- 4 个 AI 分支在情绪/节奏/牵动线索上要有差异，不能都是同一类型
- 第 5 个永远是"自己写"——保证用户灵感始终是第一位的，不被 AI 选项框住

---

## 4. 不动的部分

| 模块 | 说明 |
|------|------|
| index.html 三卡片配置 + tag 体系 | 完全不动 |
| 开篇生成逻辑 | 不动 |
| 侧边栏（提纲/线索/人物 + 时间线） | 不动，仍由剧情打点自动更新 |
| P4 文风学习（润色 + 风格档案 + 续写注入） | 不动，扩写正文时仍注入 styleProfile |
| P5 历史归档（W###/P###/S###） | 不动 |
| 去 AI 味后处理 | 不动 |
| admin.html 提示词管理 | 不动 |

---

## 5. 改动范围（仅 story.html）

### 5.1 底部交互重构

| 现状 | 变更后 |
|------|--------|
| 提示文字 + 输入框 + "继续创作"按钮 | "给走向"按钮（默认态） |
| 用户输入 → 点"继续创作" → AI 写正文 | 点"给走向" → 分支卡片区展开 |
| — | 4 个分支卡片 + "自己写" |
| — | 选中分支/自写 → AI 扩写正文 → 卡片区收起 |

输入框不再常驻，只在"自己写"被选中时展开。

### 5.2 新增 `generateBranches()`

- 组装 prompt：当前 history + storyOutline + storyClues + characterCards + tag 配置
- 调用 DeepSeek API（非流式，返回 JSON）
- 解析 4 个分支 `{ direction, hooks }`
- 渲染为分支卡片 + "自己写"选项

### 5.3 `continueStory()` 改造

- 接收参数：选中分支的 direction（或用户自写文本）
- 复用现有扩写逻辑：流式输出 + 剧情打点解析 + 侧边栏更新 + styleProfile 注入 + autoSave
- 生成完成后清空分支状态，底部回到"给走向"

### 5.4 分支状态管理

- 临时状态（不持久化）：当前展示的 4 个分支
- 选中即清空，不进入 history/storyOutline

---

## 6. 分支 prompt 要点

### 6.1 输入

- 最近若干段正文（history 尾部）
- 当前 storyOutline / storyClues / characterCards
- 世界/主角/叙事 tag 配置
- styleProfile（保持文风一致）

### 6.2 输出格式

```json
[
  { "direction": "2-3句走向描述", "hooks": "牵动的线索/人物/情绪" },
  { "direction": "...", "hooks": "..." },
  { "direction": "...", "hooks": "..." },
  { "direction": "...", "hooks": "..." }
]
```

### 6.3 约束

- 4 个走向在情绪基调（紧张/舒缓/悬疑/温情）、节奏（推进/停顿/回溯）、牵动线索上要有差异
- 每个走向必须连回至少一条现有线索或人物，不能凭空起
- 不写正文，只写走向 + 钩子

---

## 7. 数据层

无新增持久化结构。分支为临时状态，不存入 localStorage。

现有 `current_story_session` 结构不变，`continueStory()` 仍把扩写出的正文追加进 `history`，剧情打点仍更新 `storyOutline` / `storyClues` / `characterCards`。

---

## 8. API 调用

### 8.1 分支生成（新增）

```
POST /v1/chat/completions
model: deepseek-v4-flash（快速生成，不需高质量正文）
stream: false
temperature: 0.9（鼓励分支多样性）
```

返回 JSON，解析 4 个分支。

### 8.2 正文扩写（复用现有）

`continueStory()` 沿用现有流式调用（deepseek-v4-pro），仅 user prompt 中把"用户输入的方向"替换为"选中分支的 direction"或"用户自写文本"。

---

## 9. 用户操作完整流程（变更后）

```
index.html
  │ 配置世界/主角/叙事 tag + API Key
  └─ 开始创作
        │
        ▼
story.html
  ├─ AI 生成开篇（流式，不变）
  ├─ 侧边栏更新（不变）
  │
  └─ 循环：
      ├─ 点"给走向"
      ├─ AI 返回 4 分支 + 自己写
      ├─ 选分支 / 自己写
      ├─ AI 扩写正文（流式）
      ├─ 侧边栏更新
      └─ 回到"给走向"
```

---

## 10. 不在本期范围

- 开场也走分支（未来可探索）
- 分支历史回溯（看过的分支留存）
- 用户对分支的手动编辑
- 分支与 tag 体系的深度联动 UI（如高亮牵动的线索）

---

## 11. 验证标准

- 底部"给走向"按钮可点击，生成 4 个分支 + 自己写
- 分支卡片显示走向 + 钩子，钩子引用现有线索/人物
- 点分支 → AI 扩写正文，正文进入 history，侧边栏更新
- 点"自己写" → 输入框展开 → 输入后 AI 扩写
- 开篇生成、润色、保存、导出、历史记录均不受影响
- 浏览器 console 无 JS 错误
